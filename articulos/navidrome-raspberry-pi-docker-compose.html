Navidrome en Raspberry Pi con Docker Compose: música local sin nube

Navidrome es un servidor de música self-hosted, ligero y compatible con la API Subsonic. Se instala con un contenedor y te deja escuchar tu biblioteca desde el móvil sin pasar por ninguna nube.

Publicada el 25 de noviembre de 2026 · Última revisión: 25/11/2026

Qué resuelve y qué no resuelve Navidrome

Navidrome es un servidor de biblioteca: escanea tus archivos, organiza álbumes y artistas, y los sirve a clientes que entienden la API Subsonic. No reproduce por sí mismo. Tampoco transcodifica: cada cliente recibe el archivo tal cual, lo que lo hace ligero en la Pi y hambriento de ancho si tu biblioteca está llena de FLAC y la escuchas por la red móvil.

Si lo que buscas es multiroom sincronizado, este no es el servidor adecuado sin ayuda: Navidrome se combina con Snapcast u otros endpoints en lugar de sincronizar salas por sí mismo. Para un servidor que sincroniza endpoints Squeezelite, la alternativa de referencia es Lyrion Music Server, el antiguo Logitech Media Server. Ambos caben en la misma Raspberry Pi si los separas por puerto; la decisión no es uno o el otro.

Qué necesitas

Una Raspberry Pi 4 o 5 con 1 GB de RAM es suficiente para una biblioteca pequeña o mediana. El escaneo inicial puede ser lento si la música vive en un disco USB mecánico; el fix de la versión 0.64.2 que cito más abajo ayuda justo en ese caso. Necesitas también Docker Engine y Docker Compose ya instalados en el sistema operativo de la Pi.

Instalación con Docker Compose

Crea una carpeta para el proyecto y, dentro, el fichero docker-compose.yml. El bloque completo, con las variables que verifiqué este turno:

version: "3.8"
services:
  navidrome:
    image: deluan/navidrome:0.64.2
    container_name: navidrome
    restart: unless-stopped
    user: "1000:1000"          # ajústalo a tu usuario real
    ports:
      - "4533:4533"
    environment:
      ND_SCANSCHEDULE: "1h"
      ND_LOGLEVEL: info
      ND_SESSIONTIMEOUT: "24h"
      ND_BASEURL: ""
    volumes:
      - ./data:/data
      - ./music:/music:ro       # apunta a tu carpeta real de música

Usé la etiqueta 0.64.2 en lugar de latest para que una actualización no te cambie el comportamiento sin querer. Si prefieres actualización automática, cambia a :latest y vigila el feed de releases.

Primer arranque, usuario admin y escaneo

Levanta el contenedor con docker compose up -d y abre http://ip-de-tu-pi:4533. La primera vez Navidrome te pide crear un usuario administrador. El release 0.64.2 dejó de escribir la contraseña de ese primer admin en el log cuando la creación falla, así que si ves errores de arranque, ya no te arriesgas a que la contraseña quede expuesta por un fallo.

La carpeta ./music debe contener tu música organizada; se monta en solo lectura para que el servidor no toque los originales. Si no aparece nada, revisa antes los permisos del usuario 1000:1000 y que la ruta del volumen sea la que crees.

Clientes para escuchar

Al ser compatible con la API Subsonic, Navidrome funciona con varios clientes. Los que más se repiten en la documentación y foros son Substreamer para Android e iOS, Symfonium, Sonixd y DSub. El cliente solo habla con tu Pi; si estás fuera de casa, la conexión depende de tu VPN o de cómo expongas el puerto, que es una decisión de red que hay que tomar con cuidado.

Cuándo montar Lyrion en lugar de Navidrome

Si escuchas siempre en un único navegador o móvil, Navidrome es la opción con menos piezas móviles. Si quieres varias habitaciones sincronizadas con altavoces alimentados por una Pi, Lyrion con endpoints Squeezelite es el camino: ya tengo una guía de Squeezelite multiroom con ALSA que cubre esa parte del problema. Para streaming central a clientes, quédate con Navidrome.
