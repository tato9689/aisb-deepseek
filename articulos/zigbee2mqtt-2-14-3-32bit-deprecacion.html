Zigbee2MQTT 2.14.3: adiós a las plataformas de 32 bits

La versión publicada hoy deja de publicar imágenes Docker para 32 bits. Si tu coordinador corre sobre una Raspberry Pi 1, una Zero o una imagen linux/arm/v6/v7, esta es la versión en la que te quedas sin actualizaciones: migra antes de abril de 2027.

Qué cambia exactamente

El release 2.14.3 incluye una nota de deprecación: Zigbee2MQTT deja de dar soporte a plataformas de 32 bits. El fin efectivo es cuando Node.js 22 llegue a su end-of-life, en abril de 2027. A partir de ese momento, la versión mínima soportada será Node.js 24, que ya no publica builds oficiales para 32 bits.

La consecuencia inmediata es que las imágenes Docker linux/386, linux/arm/v6 y linux/arm/v7 no se actualizarán más. Las instalaciones no-Docker sobre un sistema operativo de 32 bits tampoco podrán usar una versión soportada de Node.js cuando llegue la subida a v24.

No es una rotura del coordinador ni de tu base de datos: es el fin de la ventana de actualizaciones para hardware antiguo. Tu Zigbee2MQTT seguirá arrancando mientras mantengas Node.js 22, pero te quedarás congelado en una versión sin parches.

A quién deja fuera

Si estás en una Raspberry Pi 3 o superior con Raspberry Pi OS Lite de 64 bits, no tienes que tocar nada: tu imagen linux/arm64 seguirá actualizándose con normalidad.

¿Corres Zigbee2MQTT en una Pi antigua?

La newsletter de los domingos avisa de estas roturas antes de que te pillen actualizando. Nada de «novedades»: el YAML que se rompe y la versión que lo arregla.

Comprueba tu instalación en 30 segundos

Ejecuta esto en la máquina que corre Zigbee2MQTT:

uname -m

Si devuelve aarch64 o x86_64, estás en 64 bits y no tienes que migrar. Si devuelve armv6l, armv7l o i686, tu sistema entra en la lista de afectados.

Para verlo con más detalle:

dpkg --print-architecture
cat /proc/cpuinfo | grep -m1 'model name\|Model'

En una Raspberry Pi 1 o Zero verás algo parecido a Model: Raspberry Pi Zero W Rev 1.1. Si el modelo es 3, 4 o 5 pero el SO es de 32 bits, también entras en deprecación aunque el hardware soporte 64 bits.

Migración: el camino corto

  1. Haz copia de tu configuración. Necesitas configuration.yaml, secret.yaml si lo usas, y la base de datos database.db y state.json si están en persistencia. No clones el contenedor entero.
  2. Pasa el sistema a 64 bits. En una Raspberry Pi 3/4/5 con SO de 32 bits, la vía limpia es reinstalar Raspberry Pi OS Lite de 64 bits. En una Pi 1 o Zero no hay 64 bits real: hay que cambiar de hardware o asumir que te quedarás en una versión congelada.
  3. Levanta el contenedor con la misma imagen y tu configuración. Al arrancar con koenkk/zigbee2mqtt:latest en linux/arm64, la base de datos y el coordinador se mantienen si el adaptador USB es el mismo.
  4. Comprueba el coordinador. Tras migrar, los emparejamientos Zigbee no se pierden porque viven en el adaptador, pero confirma que el pan_id y el puerto del coordinador de tu YAML siguen coincidiendo.

El punto 3 es el importante: no migres contenedor, migra configuración. El contenedor de Zigbee2MQTT es desechable; tu configuration.yaml y tu coordinador no lo son.

Qué no he podido confirmar

La nota de deprecación está en el release, pero no dice nada del soporte para imágenes 32-bit en versiones intermedias entre hoy y abril de 2027. Mientras el sistema siga con Node.js 22, probablemente sigan saliendo builds, pero no lo doy por garantizado: el anuncio solo firma el fin de las imágenes linux/386, arm/v6 y arm/v7.

No he probado la migración desde una Pi 1/Zero porque ahí no hay 64 bits real: no hay YAML que lo resuelva, solo hardware nuevo. Lo dejo señalado para no prometer una ruta que no existe.
