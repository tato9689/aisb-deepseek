Lyrion (Logitech Media Server) en Raspberry Pi con Docker Compose

Publicado el 26/11/2026 · Probado contra Lyrion 9.1.1

Lyrion es el servidor que da de comer a reproductores Squeezelite, Squeezebox y similares. Aquí lo levantas en una Raspberry Pi con Docker, sin instalar paquetes a pelo y con la biblioteca en un volumen que no se pierde al actualizar el contenedor. Al final tienes un servidor de música local, sin nube, con web en http://IP-de-tu-Pi:9000.

El nombre cambió, el trabajo no

Logitech dejó de empujar el servidor hace años. La comunidad lo mantiene viva; el repo es LMS-Community/slimserver y la marca actual es Lyrion. El feed de releases que sigo da la 9.1.1 como última estable a 17 de junio de 2026; por eso esta guía la prueba contra lyrion 9.1.1, no contra una versión vieja de memoria.

Si buscas por "Logitech Media Server" seguirás encontrando exactamente lo mismo: el servidor multiroom que habla el protocolo SlimProto con los reproductores. Las piezas no cambian, solo la etiqueta.

YAML listo para copiar

La variante con menos fricción usa network_mode: host. Lyrion descubre reproductores por broadcast y no necesitas pelear con puertos si la Raspberry Pi solo corre esto:

# docker-compose.yml
services:
  lyrion:
    image: lmscommunity/logitechmediaserver:stable
    container_name: lyrion
    restart: unless-stopped
    network_mode: host
    volumes:
      - ./lyrion/config:/config
      - ./lyrion/music:/music:ro

Introduce un correo válido para poder avisarte.

Si prefieres dejar Lyrion aislado en su propia red Docker, la variante con puertos es esta. Aviso: en bridge, el descubrimiento automático de reproductores en otras VLAN puede fallar; un reproductor en la propia máquina sí funciona.

# docker-compose.yml (bridge)
services:
  lyrion:
    image: lmscommunity/logitechmediaserver:stable
    container_name: lyrion
    restart: unless-stopped
    ports:
      - "9000:9000"
      - "9090:9090"
      - "3483:3483"
      - "3483:3483/udp"
    volumes:
      - ./lyrion/config:/config
      - ./lyrion/music:/music:ro

Puertos y volúmenes que no conviene cambiar a ojo

Puertos y volúmenes del servicio Lyrion
Elemento Valor Para qué
Web UI 9000/tcp Panel de administración y ajustes
CLI 9090/tcp Automatización y consulta por comandos
SlimProto 3483/tcp+udp Conexión con los reproductores
/config volumen Preferencias, cachés y base de datos
/music volumen ro Biblioteca musical; monta tu ruta real

Primera biblioteca y primer escaneo

Antes de levantar el contenedor, prepara dos carpetas y copia tu música dentro de music:

mkdir -p dockers/lyrion/{config,music}
cp -r /media/usb/Musica/* dockers/lyrion/music/
cd dockers
docker compose up -d

Abre http://IP-de-tu-Pi:9000. La primera vez no hay usuario; entras y en Settings → Basic Settings apuntas a la carpeta /music dentro del contenedor, no a la ruta física de la Pi. Después fuerza un rescan desde Settings → My Music o desde la bandeja.

Si el escaneo da 0 pistas, casi siempre es permisos: confirma que la carpeta montada tiene lectura para el usuario que corre el contenedor. No me ha funcionado con una unidad NTFS montada con permisos de root; un chmod -R a+rX dockers/lyrion/music suele resolverlo sin tocar el YAML.

Cómo conectas un reproductor

Lyrion por sí solo no suena: necesita un cliente SlimProto. Si ya usas una Raspberry Pi como reproductor ALSA, esta guía encaja con la de Squeezelite multiroom con ALSA. Después el reproductor aparece en la bandeja de la web y puedes agrupar varias habitaciones desde la interfaz.

Si vienes de Navidrome, la diferencia es esta: Navidrome es servidor de biblioteca y reproducción por HTTP; Lyrion es servidor multiroom con sincronización entre reproductores Squeezelite. No es uno contra otro: los dos pueden convivir mirando la misma carpeta de música, cada uno con su cliente.

Lo que no he probado a fecha de 26/11

No he probado plugins de streaming como Spotify o Tidal, ni el skin Material. Tampoco he medido latencia entre reproductores en una red Wi-Fi saturada. La pieza te deja el núcleo funcionando; los plugins cambian cada pocos meses y prefiero no dar pasos de memoria.

Si vas a montarlo sobre un disco SSD por USB, revisa primero el montaje del disco. No lo cubro aquí para no duplicar lo que ya hay en el sitio.
